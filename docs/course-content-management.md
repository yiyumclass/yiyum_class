# 강의 설명 · 판매 커리큘럼 · 등급별 품절 관리

## 운영 화면

- **강의 관리 → 차시의 영상 설명 버튼**: 줄바꿈이 있는 설명과 `http://`, `https://` 링크를 전용 편집창에서 저장합니다. 강의 제목·공개 상태와 별도 저장하며, 설명은 선택한 영상 아래에 표시됩니다. HTML은 실행하지 않고 텍스트로 표시합니다.
- **판매 커리큘럼** (`/admin/curriculum`): 홈페이지와 강의 판매 상세에 표시할 챕터·문구·과제를 편집합니다. 추가·삭제·순서 이동 후 **전체 저장**을 누릅니다. 실제 강의, 영상, 수강 진도와는 별도 데이터입니다.
- **상품 관리 → SNS 클래스 등급별 판매 관리**: 베이직·부스터·프리미엄을 각각 판매 중/품절로 변경합니다. 품절이어도 가격·혜택은 남고 해당 등급의 구매 버튼만 비활성화됩니다.

초기 판매 커리큘럼은 고객이 제공한 10챕터·89개 번호 항목입니다. 번호가 붙은 과제 5·11·15·23강은 89강에 포함하며, 별도로 배치한 과제 13개는 강 수에 더하지 않습니다. 총 항목은 102개, 그중 과제는 17개입니다. 초기 데이터를 다시 적용해도 관리자가 편집한 내용을 덮어쓰지 않습니다.

동시에 편집한 다른 관리자가 먼저 저장하면 오래된 버전의 저장을 거절합니다. 입력 내용은 화면에 유지되며, **최신 내용 다시 불러오기**는 확인 후 저장하지 않은 편집을 버리고 서버 데이터를 다시 읽습니다.

영상 설명도 마지막으로 읽은 저장 시각을 비교하므로 다른 관리자의 변경을 덮어쓰지 않습니다. 저장 성공·실패 뒤에도 입력 내용을 유지하고, 저장하지 않은 설명을 닫을 때는 확인을 받습니다. 설명 충돌이 발생하면 필요한 입력을 복사한 뒤 페이지를 새로고침하여 최신 설명부터 다시 편집합니다.

## 배포 순서

이 브랜치에서는 운영 DB를 변경하지 않습니다. 코드 배포 전에 아래 순서대로 적용해야 저장 기능을 사용할 수 있습니다.

1. `supabase/migrations/20261005100000_add_lesson_descriptions.sql`
2. `supabase/migrations/20261005101000_create_marketing_curricula.sql`
3. `supabase/migrations/20261005102000_seed_marketing_curriculum.sql`

1번은 기존 `lessons`, 강의 범위·수강권 및 관리자 감사 로그 스키마를 사용합니다. 2번은 관리자 기반 스키마를, 3번은 2번을 전제로 합니다. 등급별 품절은 기존 `products.status`를 재사용하므로 별도 상태 스키마가 없습니다.

마이그레이션 전에는 기존 강의 재생을 유지하고 영상 설명 저장만 비활성화합니다. 판매 커리큘럼은 초기 문구를 표시하되 저장할 수 없다는 안내를 보여 줍니다. 일반적인 DB 오류에서는 오래된 초기 문구로 덮어쓰지 않고 오류 상태를 표시합니다.

운영 적용 후에는 관리자 권한으로 설명 저장·새로고침, 커리큘럼 문구 저장·공개 페이지 반영, 등급별 상태 변경·새 주문 차단을 확인해야 합니다. 판매 상태 검증은 운영 중인 등급을 임의로 바꾸지 말고 별도 검증 환경에서 먼저 진행합니다.

## 결제·수강권 경계

- 품절은 **새 주문 생성**을 막습니다. 이미 만들어진 진행 중 주문의 승인·정산·복구는 기존 흐름을 유지합니다. 결제가 끝난 후 상태가 바뀌었다고 수강권 발급을 거절하지 않습니다.
- 결제 승인, 환불, 복구 로직은 이번 변경에서 수정하지 않습니다.
- 기존 유효한 수강권은 품절 때문에 취소되지 않습니다. 설명 조회 역시 수강권 유효 기간, 취소 여부, 구매한 챕터 범위와 실제 콘텐츠 공개 상태를 확인합니다.
- 판매 커리큘럼은 강의·차시·상품에 대한 외래 키가 없습니다. 실제 강의 삭제·비공개와 판매 문구 편집은 서로 영향을 주지 않습니다.

## 로컬 검증

```sh
npm test
npm run lint
npx tsc --noEmit
npm run build
```

DB 검증 스크립트는 운영 연결 문자열이나 `.env.local`을 읽지 않고 메모리 안의 PostgreSQL만 사용합니다. 테스트 실행용 패키지는 프로젝트 외부에 설치할 수 있습니다.

```sh
npm install --prefix /tmp/yiyume-course-validation --no-audit --no-fund --ignore-scripts --package-lock=false @electric-sql/pglite
PGLITE_MODULE_PATH=/tmp/yiyume-course-validation/node_modules/@electric-sql/pglite/dist/index.js node scripts/verify-course-content-db.mjs
```

이 검증은 새 마이그레이션의 SQL 실행, 익명·일반회원·비활성 관리자 권한 거절, 정상 저장과 감사 로그, 버전 충돌, 감사 실패 시 롤백, 초기 데이터 재적용, 설명 RLS, 품절 후 기존 수강권, 챕터별 권한, 만료·취소 수강권, 길이 제한 및 삭제 범위를 확인합니다. 기존 강의 스키마는 필요한 열을 가진 로컬 fixture를 사용하므로 운영 전체 스키마의 적용 검증을 대체하지는 않습니다.

화면 검증은 로컬 HTTP fixture와 별도 브라우저 세션으로 수행합니다. 운영 DB·회원·결제는 사용하지 않습니다. 홈·판매 상세의 10챕터/89강 표시, 390px 모바일 화면, 관리자 저장·충돌 안내, 등급별 품절 상태, 영상 설명의 안전한 링크/HTML 비실행을 확인합니다. 실제 영상 스트리밍이나 실결제 검증은 이번 작업의 범위에 포함하지 않습니다.
