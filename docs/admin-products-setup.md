# 어드민 2단계: 상품 관리 설정

> 이 문서는 개발·배포 담당자용이다. 실제 운영 관리자는 SQL을 실행하지 않으며,
> 관리자 화면에서 상품 등록과 수정만 수행한다. 마이그레이션은 서비스 배포 전에
> 개발자가 한 번 적용한다.

## 구현 범위

- `/admin/products` 상품 목록, 유형·상태 필터와 검색
- 강의·전자책 공통 상품 등록
- 등록 상품의 상품명·설명·판매가·이용 기간·상태 수정
- `작성 중`, `판매 중`, `판매 중지`, `보관` 상태 관리
- 기간제 또는 기간 제한 없는 이용 기간 설정
- 관리자 권한을 다시 확인하는 Server Action과 DB RLS
- 상품 등록·수정·상태 변경 시 `admin_audit_logs` 자동 기록

상품은 판매 단위만 관리한다. 강의의 챕터·차시와 전자책 파일은 다음 단계에서
`courses`, `course_sections`, `lessons`, `ebooks`로 분리해 연결한다.

## 1. 상품 테이블 생성

Supabase SQL Editor에서 아래 파일 전체를 실행한다.

`supabase/migrations/20260714110000_create_products.sql`

이 마이그레이션은 다음 작업을 함께 수행한다.

- `public.products` 생성
- 현재 `이윰 SNS 수익화 클래스` 상품 초기 등록
- 판매 중 상품은 공개 조회 허용
- 활성 관리자만 전체 조회·등록·수정 허용
- 실제 삭제 권한은 제공하지 않고 `archived` 상태 사용
- 변경 관리자와 이전·변경 상태를 감사 로그에 기록

기본 상품 테이블 SQL을 이미 실행했다면, 변경 필드와 변경 전후 값을 더 자세히
기록하도록 아래 파일도 이어서 실행한다.

`supabase/migrations/20260714120000_expand_product_audit_log.sql`

결제 연동 전 무료 신청 테스트를 사용하려면 강의 마이그레이션 적용 후 아래 파일도
실행한다.

`supabase/migrations/20260715150000_create_free_enrollments.sql`

이 마이그레이션은 다음 작업을 수행한다.

- 강의·전자책 상품 가격을 0원으로 변경
- 테스트용 전자책 상품을 판매 중·0원 상태로 등록
- 사용자별 강의·전자책 이용권과 본인 조회 RLS 생성
- 로그인 사용자의 0원 상품 즉시 신청 RPC 생성
- 신청한 사용자만 강의실 영상과 진도 저장 기능을 사용할 수 있도록 제한

## 2. 화면 확인

관리자 계정으로 다시 `/admin/products`에 접속한다.

- 상단에 `DB 연결됨`이 표시되어야 한다.
- `새 상품 등록` 버튼이 활성화되어야 한다.
- 기존 SNS 수익화 클래스가 판매 중 상태로 표시되어야 한다.
- 각 DB 상품 우측의 `수정`을 누르면 기존 가격과 상품 정보가 채워져야 한다.
- 무료 신청 모드에서는 판매가 입력이 0원 읽기 전용으로 표시되어야 한다.
- 저장 후 목록의 가격, 이용 기간, 상태와 최근 수정일이 갱신되어야 한다.

SQL 실행 전에도 화면은 열리지만, 현재 코드 카탈로그를 읽기 전용으로 보여주며
상품 등록 버튼은 비활성화된다.

## 상태 운영 원칙

| 상태 | 의미 | 공개 판매 |
| --- | --- | --- |
| `draft` | 작성·검수 중 | 아니요 |
| `active` | 판매 중 | 예 |
| `paused` | 일시 판매 중지 | 아니요 |
| `archived` | 운영 종료 후 보관 | 아니요 |

주문·수강권 기록과의 연결을 고려해 상품 행은 삭제하지 않는다. 운영 종료 상품은
`archived`로 보관한다.

## 수정 운영 원칙

- 상품명, 설명, 판매가, 이용 기간, 판매 상태, 이미지·상세 경로는 수정할 수 있다.
- 상품 유형과 상품 주소(`slug`)는 주문 및 콘텐츠 연결 키로 사용하므로 생성 후에는
  화면에서 수정하지 않는다.
- 판매가 변경은 기존 주문 금액을 바꾸지 않고, 이후 결제에 적용할 상품 가격만 바꾼다.
- 모든 변경은 Server Action에서 관리자 권한을 다시 확인하며, 감사 로그에 변경 필드와
  변경 전후 값을 남긴다.

## 현재 공개 판매 화면과의 연결 범위

`/`, `/courses`, 강의 상세와 `/checkout`은 상품 DB의 판매 상태·가격·이용 기간을 사용한다.
결제 연동 전에는 애플리케이션의 무료 신청 모드가 판매가를 0원으로 고정한다. 로그인 사용자가
무료 신청을 완료하면 서버 RPC가 이용권을 발급하고 `/my`에 해당 콘텐츠가 즉시 표시된다.

무료 신청 모드에서는 어드민 판매가도 0원 읽기 전용으로 표시한다. 운영자가 입력한 금액을
조용히 무시하지 않으며, 결제 도입 시 무료 모드를 끈 뒤 판매가 편집을 다시 활성화한다.

결제 도입 시에는 무료 신청 모드를 끄고, 결제 성공 웹훅이 동일한 이용권 테이블에
`payment` 출처로 권한을 발급하도록 연결한다.

## 품절과 세일 가격

`supabase/migrations/20260807100000_add_sold_out_status_and_list_price.sql` 를
Supabase SQL Editor에서 실행한다. **이 마이그레이션은 코드 배포보다 먼저 적용한다.**
어드민 상품 목록이 `list_price_krw` 를 조회하므로, 컬럼이 없으면 목록이 비어 보인다.

### 판매 상태

| 상태 | 공개 목록 | 결제 | 쓰는 때 |
| --- | --- | --- | --- |
| 판매 중 `active` | 노출 | 가능 | 평소 |
| 품절 `sold_out` | 노출 | 불가 | 이번 기수 마감, 다음 모집 예정 |
| 판매 중지 `paused` | 비노출 | 불가 | 상품을 아예 내릴 때 |
| 작성 중 `draft` | 비노출 | 불가 | 준비 중 |
| 보관 `archived` | 비노출 | 불가 | 접은 상품 |

품절은 카드와 상세 페이지, 커리큘럼이 그대로 보이고 결제만 막힌다. 다음 기수를
기다리게 하려면 상품이 보여야 하기 때문이다. 차단은 앱이 아니라
`create_toss_payment_order` 와 `claim_free_product` 가 `status = 'active'` 를
요구하는 데서 일어나므로, 결제 주소를 직접 열어도 통과하지 못한다.

### 정가

`정가` 를 비워두면 세일 표시가 붙지 않는다. 값을 넣으면 홈, 강의 목록, 강의 상세에
취소선 정가와 할인율이 판매가와 함께 표시된다. 정가는 판매가보다 낮을 수 없다.
DB 제약과 폼 검증이 모두 막는다.

세일 운영은 정가를 그대로 두고 판매가만 내렸다 올린다.

## 줌 라이브 1:1 컨설팅

`supabase/migrations/20260807110000_add_consulting_product_type.sql` 를 실행하면
상품 유형에 `consulting` 이 열린다. 앞선 품절·정가 마이그레이션 다음에 적용한다.

컨설팅은 VOD 재생도 파일 내려받기도 아니다. 결제하면 이용권이 발급되고, 카카오톡과
이메일로 설문 폼을 보낸 뒤 사람이 일정을 잡는다. 이행 방식이 다르기 때문에 유형을
나눴다. 판매 페이지 생김새가 다르다는 이유만으로는 유형을 늘리지 않는다.

### 상품 등록

관리자 → 상품 관리 → 상품 등록에서 **1:1 컨설팅** 을 고르고 아래대로 넣는다.

| 항목 | 값 |
| --- | --- |
| 상품 주소 | `zoom-consulting-1on1` |
| 상품명 | 줌 라이브 1:1 컨설팅 |
| 판매가 | 187000 |
| 정가 | 550000 |
| 이용 기간 | 기간 제한 없음 |

**상품 주소는 반드시 `zoom-consulting-1on1` 이어야 한다.** 상세 원고가
`src/lib/store/consulting-copy.ts` 에서 이 주소로 연결된다. 주소가 다르면 히어로만
뜨고 그 아래 상세가 비어 보인다.

썸네일 경로를 넣으면 목록 카드와 상세 히어로에 함께 쓰인다.

### 상세 원고 수정

컨설팅 상세 문구는 관리자에서 편집하지 않는다. `src/lib/store/consulting-copy.ts`
를 고치고 배포한다. 판매 문구는 한 번 확정되면 자주 바뀌지 않는 반면, 문구마다
편집 화면을 붙이면 유형이 늘 때마다 그 화면을 또 만들어야 한다.

가격, 정가, 품절, 썸네일은 원고 파일에 두지 않는다. 그 값들은 상품 DB에 있어야
운영자가 직접 바꿀 수 있고, 실제로 히어로가 상품 DB에서 읽는다.

나중에 운영자가 직접 문구를 고쳐야 할 때가 오면, `ConsultingCopy` 모양 그대로
테이블로 옮기고 렌더러는 손대지 않는다.

## 자료실과 자료 파일

`supabase/migrations/20260809100000_create_product_files_and_detail.sql` 를 실행한다.
앞선 마이그레이션 두 개 다음에 적용한다. 이 마이그레이션은 `product-files` 비공개
버킷과 `product_detail_items` 테이블을 만든다.

### 자료 등록

관리자 → 상품 관리 → 상품 등록에서 **전자책** 을 고르고 판매가를 `0` 으로 두면
무료 자료가 된다. 등록한 뒤 목록에서 **자료 구성** 을 눌러 파일과 안내 항목을
채운다.

| 화면 | 넣는 것 |
| --- | --- |
| 상품 수정 | 상품명, 상품 설명(카드 한 줄), 상세 소개(문단), 썸네일 |
| 자료 구성 | 자료 파일, "이런 게 들어있어요" 항목 |

상세 소개는 빈 줄로 문단을 나눈다. 항목은 제목만 넣어도 되고 설명을 덧붙여도 된다.

### 자료 파일이 전달되는 길

파일은 비공개 버킷에 두고 주소를 화면에 심지 않는다. 회원이 마이 클래스에서
내려받기를 누르면 `/api/library/{slug}/download` 가 이용권을 다시 확인하고 60초짜리
서명 주소를 발급한다. 무료 자료의 목적이 회원 확보라, 주소 하나가 공유되면 그
목적이 통째로 무너진다.

이용권이 없을 때와 자료가 없을 때 같은 응답을 준다. 어느 쪽인지 알려주면 남의
이용권 보유 여부를 떠볼 수 있다.

### 미리보기와 잠금

`supabase/migrations/20260809110000_create_product_page_previews.sql` 를 이어서
실행한다.

PDF 를 올리면 관리자 브라우저가 페이지를 이미지로 그려 함께 올린다. 서버에 PDF
렌더링을 넣으면 네이티브 의존성이 따라오는데, 자료 업로드는 어쩌다 한 번 하는
일이라 그 비용을 치를 이유가 없다.

`자료 구성` 화면에서 **미리보기 장수** 를 정한다. 앞쪽 그만큼은 로그인하지 않아도
보이고, 나머지는 신청한 회원에게만 열린다.

잠근 페이지는 화면에서 가리는 것이 아니라 서버가 주소를 만들지 않는다. 가려두기만
하면 개발자 도구로 걷어낼 수 있다. 몇 장이 더 있는지는 알려준다. 그래야 가입할
이유가 생기고, 주소가 없으니 걷어낼 것도 없다.

원본 PDF 내려받기는 그대로 둔다. 이메일 문구처럼 복사해 쓰는 자료는 이미지로만
보면 쓸모가 반으로 준다.

### 화면

- `/library` 자료실 목록. 유료 클래스와 섞지 않는다. 무료 자료가 클래스 사이에
  끼면 클래스 가격이 싸 보인다. 자료실 안에서도 `전자책`(유료)과 `무료 자료`를
  구역으로 나눈다. 같은 이유로 파는 것과 나눠주는 것을 한 줄에 세우지 않는다.
  가르는 축은 판매가다. 전자책을 한시적으로 0원에 풀면 그때는 실제로 무료 자료
  역할을 하므로 그 구역으로 옮겨가는 것이 맞다.
- `/library/{slug}` 자료 상세. 클래스 상세와 같은 화면을 쓰고 주소만 나눈다.
- 상단 메뉴의 `자료실` 이 여기로 온다. 예전에는 결제 주소로 바로 갔다.
